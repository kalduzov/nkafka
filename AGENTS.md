# NKafka Project Information for AI Agents

This document provides essential information for AI agents working on the NKafka project.

## Project Overview

NKafka is a high-performance, fully managed Kafka client for .NET, written in C#. It aims to provide a native .NET implementation of the Kafka
protocol without relying on native librdkafka.

- **Primary Language**: C# 13
- **Target Frameworks**: .NET 8.0, .NET 9.0
- **Key Features**: High performance, OpenTelemetry support, centralized package management.

## Project Structure

- `src/NKafka`: The core library containing the Kafka client implementation.
    - `Clients/`: Producer and Consumer implementations.
    - `Protocol/`: Kafka protocol implementation, including serialization and primitives.
    - `Messages/`: Generated and manual Kafka protocol message classes.
    - `Serialization/`: Built-in serializers and deserializers.
- `src/NKafka.MessageGenerator`: A tool that generates C# code for Kafka protocol messages from JSON specifications.
- `kafka/`: A submodule or directory containing the official Apache Kafka repository, used for protocol specifications.
- `tests/`: Unit and integration tests using xUnit and FluentAssertions.
- `benchmarks/`: Performance benchmarks using BenchmarkDotNet.
- `samples/`: Example usage of the library.

## Coding Guidelines

### Code Generation

- **DO NOT** manually edit files with the `.g.cs` extension. These are generated by `NKafka.MessageGenerator`.
- To extend a generated message, use `partial class` in a separate `.cs` file within the same namespace.
- Message specifications are typically derived from the official Kafka JSON definitions found in the `kafka` directory.

### C# Language Features

- Use the latest C# 13 features where appropriate:
    - Primary constructors.
    - Collection expressions (`[...]`).
    - `ref readonly` and other performance-oriented features.
- The project allows `unsafe` code for performance optimizations.

### Static Analysis and Quality

- The project uses **PVS-Studio** for static analysis. Include the PVS-Studio header in new manual files.
- **Nullable Reference Types** are enabled and should be strictly followed.

### Centralized Package Management

- Package versions are managed centrally in `Directory.Packages.props`. Do not specify versions in `.csproj` files.

## Development Workflow

1. **Initialize/Update**: Run `update_repo.ps1` (Windows) or `update_repo.sh` (Linux) to sync submodules and tools.
2. **Build**: Use `dotnet build` from the root directory.
3. **Generate Messages**: If protocol specifications change, run the `NKafka.MessageGenerator` tool.
4. **Test**: Use `dotnet test` to run all tests. Ensure that all tests pass before submitting changes.

## Protocol Implementation

- Kafka messages are implemented using `IRequestMessage` and `IResponseMessage` interfaces.
- Each message version is handled via a `Version` property.
- Pay attention to `ApiVersion` when implementing or extending message logic.

## Performance Considerations

- NKafka is designed for high performance. Avoid unnecessary allocations in the hot path.
- Use `System.IO.Pipelines` and `Span<T>`/`Memory<T>` where appropriate.
- Monitor `benchmarks/` when making changes to the data path.
