# NKafka

NKafka is a .NET client library for Apache Kafka, providing a simple and efficient way to produce and consume messages from Kafka clusters. It is
designed to be easy to use and integrate with existing .NET applications, while also providing advanced features for handling complex Kafka scenarios.

## Cluster

NKafka provides a simple abstraction over Kafka clusters, allowing you to easily manage multiple Kafka clusters from a single application.

Кластер это центральный компонент библиотеки и именно он является точкой входа для работы с Kafka. После подключения к кластеру Кафки, из него
можно уже создавать нужных клиентов Producer и Consumer.

Кроме того, именно тут находится единая точка для администраторских операций, таких как создание и удаление тем, управление ACL и т.д.

Если объект кластера будет уничтожен — все его внутренние ресурсы и транспортные соединения будут закрыты. Текущие созданные клиенты после этого будут
получать ошибку.

Конфигурация кластера представляет собой минимальный набор параметров, необходимых для подключения к конкретному кластеру.

Все они относятся к сетевым настройкам, настройкам безопасности, параметрам версионирования и другим аспектам работы протоколов, discovery серверов
и обновления общей информации по топологии кластера.

Все клиенты, порожденные от этого класса, будут использовать эти настройки на всем протяжении жизни объекта.

## Connection Pool

Другим отличием текущей библиотеки является использование пула соединений для работы с Kafka. Это позволяет улучшить производительность и стабильность
приложения, а также снизить нагрузку на Kafka кластер.

В отличии от других клиентов — nkafka старается не создавать лишних коннектов для своей работы. Например работа, всех созданных продюсеров для
одного кластера — ведется через одно физическое соединение. Однако, если внутренние алгоритмы понимают, что текущего сетевого соединения будет
недостаточно,
будет создано еще одно соединение.

Архитектура кафки подразумевает, что для каждого консьюмера должно создаваться всегда выделенное соединение. Поэтому для каждого консьюмера всегда
создается отдельное соединение и работа производится именно через него.

Если брать, к примеру, библиотеку confluent.kafka, где для каждого порожденного клиента создается свое соединение,
то в нашем случае мы получаем экономию накладных расходов на создание соединений и улучшаем общую производительность приложения.

Кроме того весь сетевой стек, используемый в nkafka работает на сокетных событиях, и обрабатывается небольшим пулом выделенных потоков/либо работает
на текущем ThreadPool.
В отличии от других библиотек — nkafka не создает лишних потоков, что позволяет ей эффективно работать в средах типа kubernetes,
в которых могут быть заданы лимиты на количество потоков.
