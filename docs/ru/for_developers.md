## Зависимость от других клиентов

Для получения описаний протокола используется исходный код клиента Kafka на Java. Описания контрактов хранятся в нём в файлах `json`.

На основе этих файлов встроенный инструмент создаёт контракты сообщений и методы сериализации и десериализации протокола.

Базовая ветка и версия клиента Java для этого репозитория — **4.3**.

> При изменении алгоритмов генерации контрактов необходимо повторно создать все сообщения и при необходимости тесты для них.

## Развёртывание инфраструктуры

Папка **infra** содержит инструменты для развёртывания **Kafka** в **Docker** для проверки клиента.

> Согласно текущему описанию инфраструктуры, полностью работоспособны только `docker-compose.yml` и `docker-compose.big-cluster.yml`. Остальные варианты развёртывания требуют доработки.

> Для запуска интеграционных тестов также требуется развернуть окружение из `docker-compose.yml`.

Целевая матрица проверок с настоящими брокерами и требования к окружению сквозных испытаний описаны в:

- [Плане проверок с настоящей Kafka](../../spec/real-kafka-e2e-plan.md).

## Языки документации

Английский — базовый язык в `docs/en`; русская версия ведётся в `docs/ru`. Обе папки должны содержать одинаковые относительные пути файлов, порядок документов, структуру разделов, примеры и детали контрактов. Создавайте или обновляйте обе версии одним изменением. Отсутствие перевода означает незавершённое изменение документации.

Идентификаторы и имена файлов сохраняются одинаковыми для всех языков. Пояснения и заголовки переводятся, примеры кода остаются эквивалентными. Ссылки внутри языковой папки ведут на тот же язык, если перевод существует. Каждая страница ссылается на соответствующую страницу другого языка. `docs/index.md` — общая страница выбора языка.

Внутренние спецификации в `spec/` ведутся отдельно от документации библиотеки и подчиняются правилам репозитория. XML-комментарии исходного кода остаются на английском; связанные руководства и пояснения должны быть доступны на обоих языках документации.
