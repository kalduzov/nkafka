# План реализации шага 02

Исходный документ: [02-configuration-results-errors.md](02-configuration-results-errors.md).

Каждый шаг выполняется отдельным изменением, сопровождается тестами и проверкой. После завершения шага работа останавливается до проверки пользователем; коммит выполняется только после этой проверки.

## Шаг 1. Модель настроек и независимое копирование — готово к проверке

- добавить общую настройку `ClientDisposeTimeoutMs`;
- добавить `ProducerConfig.EnqueueTimeoutMs`;
- удалить `ProducerConfig.EnableDeliveryReports`;
- сделать `BaseFrom` и `MergeFrom` полными для общих настроек;
- копировать изменяемые вложенные данные независимо;
- обновить перенос общих настроек для потребителя и транзакционного продюсера;
- добавить модульные проверки значений по умолчанию, переноса свойств и независимости копий.

## Шаг 2. Валидация настроек — готово к проверке

- добавить проверки размеров, сроков, переполнения арифметики и совместимости параметров;
- сохранить существующие валидаторы вложенных настроек;
- добавить проверки транзакционных ограничений;
- покрыть проверки модульными тестами.

## Шаг 3. Nullable-данные сообщения и заголовки — готово к проверке

- сделать ключ и значение `Message` nullable;
- сохранить различие `null` и пустого массива;
- обновить добавление nullable-значений заголовков;
- проверить сериализацию и выбор раздела для обоих представлений.

## Шаг 4. Контракт ошибок и результата доставки

- добавить `ProducerError` и `ProducerLocalError`;
- добавить `ErrorCodes.ClientError`;
- расширить `MessageDeliveryResult` свойством `Error`;
- добавить проверки допустимых сочетаний кодов и локальных причин.

## Шаг 5. Поведение продюсера

- убрать молчаливое увеличение `DeliveryTimeoutMs`;
- обновить расчёт размеров nullable-данных;
- согласовать статусы `NotPersisted` и `PossiblyPersisted` с границей начала записи;
- обеспечить одинаковый результат для задачи и обработчика доставки.

## Шаг 6. Документация и итоговая проверка

- обновить XML-документацию публичных типов;
- обновить руководства в `docs/en` и `docs/ru`;
- выполнить сборку и сфокусированные тесты;
- отдельно зафиксировать результат проверок, требующих доступного брокера.
