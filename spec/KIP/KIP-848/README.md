# KIP-848. Новый протокол групп потребителей NKafka

Статус: отложено для отдельного проектирования. Этот документ сохраняет зависимость, обнаруженную при согласовании [шага 06 KIP-98](../KIP-98/06-consumer-offsets-and-processing.md), и не означает согласования интерфейсов или готовности реализации.

## Зачем нужен отдельный этап

Потребитель NKafka сейчас использует классический путь `JoinGroup`/`SyncGroup`. Наличие схем сообщений нового протокола не означает, что его поддерживает действующий потребитель. В шаге 06 KIP-98 согласована только работа с группой, имеющей динамическое членство в классическом протоколе.

Новый протокол групп по KIP-848 использует `ConsumerGroupHeartbeat` и эпоху участника вместо поколения классической группы. Его внедрение меняет управление членством и перераспределением разделов в потребителе, а также сведения, которыми транзакционный продюсер подтверждает смещения группы. Оно не совпадает с переходом на [новый серверный протокол транзакций](../KIP-98/09-server-side-transaction-protocol.md) по KIP-890.

## Что предстоит спроектировать

- Выбор режима группы, совместимость с брокерами и поведение при неподдерживаемом режиме.
- Получение назначений и переходы состояния членства через `ConsumerGroupHeartbeat`, включая потерю владения разделами.
- Представление эпохи участника в сведениях о группе без ошибочного смешения с поколением классической группы; влияние на согласованный `IConsumer.GetGroupMetadata()`.
- Передачу актуальных сведений о членстве в транзакционное подтверждение смещений, версии запросов и защиту от прежнего участника группы.
- Восстановление после перераспределения, смены координатора, потерянного ответа и перезапуска процесса; совместные испытания потребителя и транзакционного продюсера на поддерживаемых версиях Kafka.

Постоянное членство в классической группе не добавляется автоматически вместе с KIP-848; для него потребуется отдельное решение о настройках и времени жизни потребителя.
