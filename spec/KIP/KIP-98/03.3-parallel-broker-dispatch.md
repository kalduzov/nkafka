# Шаг 03.3. Параллельная отправка пакетных запросов брокерам

Статус: черновик для отдельного обсуждения. Создание документа не означает согласования новых решений или реализации функциональности.

## Цель и зависимости

Зависимость: шаги 03.1 и 03.2. Устранить последовательную отправку готовых пакетов разным брокерам в `MessagesSender`, сохранив порядок пакетов в каждом разделе темы.

## Текущее состояние

`MessagesSender` получает готовый пакет, определяет брокер, ожидает завершения отправки и обработки ответа и лишь затем переходит к следующему пакету. Из-за ожидания внутри обхода пакеты, адресованные разным брокерам, отправляются последовательно. Медленный брокер ограничивает пропускную способность независимых разделов на других брокерах.

## Границы

Входят группировка готовых пакетов по брокеру, параллельная отправка независимых групп, сопоставление ответов с группой и сохранение порядка в разделе темы. Не входят неделимая запись кадров в общем соединении, справедливость между разными клиентами, общий предел незавершённых запросов и изменение сетевого клиента. Эти правила определяются общей спецификацией планирования запросов кластера.

## Предлагаемая модель

1. Отправитель получает готовые неизменяемые пакеты из накопителя.
2. Пакеты группируются по брокеру, назначенному текущими метаданными.
3. Для каждого брокера формируется Produce-запрос в пределах `MaxRequestSize` и запускается независимая асинхронная отправка.
4. Отправитель ожидает завершения всех запущенных групп, обрабатывает их ответы и планирует повторы согласно шагу 03.2.

В один запрос входит не более одного пакета одного раздела темы. Следующий пакет того же раздела не отправляется, пока предыдущий не получил окончательный исход либо не передан в согласованный механизм повтора. Ошибка или задержка одного брокера не задерживает формирование и отправку групп другим брокерам.

## Проверки

- Два брокера: задержка ответа одного не задерживает отправку другому.
- Несколько разделов одного брокера: пакеты корректно объединяются в один Produce-запрос.
- Несколько пакетов одного раздела: порядок сохраняется.
- Ошибка одной группы не отменяет и не искажает исход другой.
- Общий сетевой путь не допускает смешения кадров и ответов.

## Требующие решения вопросы

1. Допустимое число одновременно отправляемых групп продюсера и его связь с общим пределом соединения.
2. Действия при изменении лидера между группировкой и записью запроса.
3. Измеримые целевые показатели прироста пропускной способности для шага 07.

## Условия завершения

Проверки подтверждают одновременную отправку групп разным брокерам, порядок пакетов в каждом разделе темы и независимый окончательный исход каждой группы. Измерения показывают устранение последовательной задержки на нагрузке с несколькими брокерами.
