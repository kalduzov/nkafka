# Шаг 09. Новый серверный протокол транзакций Kafka

Статус: запланировано после готовности классического транзакционного режима к промышленной эксплуатации. Этот документ не расширяет требования шагов 01–07 и не разрешает использовать новый режим до отдельного согласования.

## Цель

Добавить поддержку режима Kafka 4.x с финализированной возможностью `transaction.version=2`, описанного в KIP-890. Публичные интерфейсы не меняются: выбор протокола остаётся внутренней деталью `ITransactionalProducer`.

## Исходная граница

Шаг 05 реализует только классический KIP-98: клиент до первой отправки записи в раздел темы выполняет `AddPartitionsToTxn`. Этот путь остаётся режимом совместимости и должен работать в том числе с Kafka 4.x.

## Предмет отдельного проектирования

- Получение и хранение финализированной возможности `transaction.version` из `ApiVersions`.
- Переключение протокола только между транзакциями, без смены режима внутри активной транзакции.
- Обновление эпохи продюсера для каждой транзакции и новый путь первой отправки, при котором раздел добавляет брокер.
- Версии и поля `FindCoordinator`, `InitProducerId`, Produce, операций со смещениями и `EndTxn`, а также новые ответы и коды ошибок.
- Возврат к классическому пути при выключении возможности кластера.
- Испытания на Kafka 4.x: включённый и выключенный режим, обновление и понижение возможности, смена координатора, потерянные ответы и проверка `read_committed`.

Решения принимаются в этом документе отдельно. До этого NKafka не выбирает `transaction.version=2` автоматически, даже если брокер сообщает соответствующие версии запросов.
