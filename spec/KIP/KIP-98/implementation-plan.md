# План реализации KIP-98: публичные интерфейсы продюсеров

Цель: полностью перенести требования `spec/KIP/KIP-98/01-public-interfaces.md` в исходный код, тесты и документацию NKafka.

Работа выполняется последовательно. После каждого шага выполняются относящиеся к нему проверки; до отдельного подтверждения следующий шаг не начинается и коммит не создаётся.

## Шаг 1. Основа публичного контракта — принят

- Добавить `ITransactionalProducer` и `IProducerTransaction` с XML-документацией.
- Добавить отдельный `TransactionalProducerConfig` с транзакционными значениями по умолчанию.
- Зафиксировать тестами состав новых типов и начальные значения конфигурации.
- Проверить сборку и тесты затронутого проекта.

Результат: новые контракты существуют в коде, но старый путь создания и внутренняя реализация ещё не переключены.

## Шаг 2. Разделение обычного и транзакционного продюсеров — принят

- Удалить транзакционные члены из `IProducer`.
- Создать реализации `ITransactionalProducer` и `IProducerTransaction` поверх существующих внутренних компонентов.
- Удалить старые публичные `InitTransactionsAsync`, `BeginTransaction`, `CommitTransactionAsync`, `AbortTransactionAsync` и `SendOffsetsToTransactionAsync`.
- Добавить проверки состава интерфейсов.

Сведение обычного продюсера к окончательному минимальному контракту выполняется вместе с изменением владения и освобождения ресурсов на шаге 3, чтобы не разделять связанные изменения.

Дополнение по решению пользователя: callback-методы обычного продюсера сохраняются как часть публичного контракта и не применяются к транзакционному продюсеру.

## Шаг 3. Создание клиентов и владение ресурсами — принят

- Заменить `BuildProducer` на `CreateProducer` с созданием нового экземпляра.
- Добавить асинхронное `CreateTransactionalProducerAsync` с полной инициализацией до возврата.
- Убрать реестр обычных продюсеров из публичного поведения.
- Перевести продюсеров и транзакцию на `IAsyncDisposable` без `IDisposable` и `CloseAsync`.
- Проверить освобождение клиента без закрытия кластера и обработку частично созданных ресурсов.

## Шаг 4. Конфигурация и перегрузки создания — выполнен, ожидает проверки

- Реализовать наследование и копирование `ProducerConfig` / `TransactionalProducerConfig`.
- Реализовать проверку ID, конфликтов явного ID и ID конфигурации, а также неизменность входной конфигурации.
- Добавить перегрузки с ID, конфигурацией и функцией настройки.
- Добавить проверку совместимости `EnableIdempotence` и `Acks` до сетевой инициализации.
- Добавить соответствующие тесты всех перегрузок и граничных случаев.

## Шаг 5. Ограничение занятых `TransactionalId` — выполнен

- Реализовать атомарное резервирование ID в пределах одного `IKafkaCluster`.
- Запретить повторное и одновременное создание занятого ID.
- Освобождать ID после неудачного создания и полной очистки клиента.
- Проверить гонки создания, закрытия кластера и инициализации.

Реализовано атомарное резервирование до сетевой инициализации и освобождение после полной очистки клиента.

## Шаг 6. XML-документация и интеграции — выполняется

- Довести XML-документацию всех публичных типов, методов, параметров, результатов и исключений.
- Обновить `NKafka.AspNetCore`, тестовые подмены, примеры и публичный API-файл.
- Обновить руководство одновременно в `docs/en` и `docs/ru`, включая ограничение регистрации транзакционного продюсера как общего `singleton`.
- Проверить ссылки и включение документов в решение.

## Шаг 7. Итоговая проверка

- Запустить сборку затронутых проектов для .NET 8 и .NET 9.
- Запустить модульные тесты новых и изменённых частей.
- Отдельно зафиксировать результат интеграционной проверки с брокером; недоступный брокер не считать ошибкой реализации.
- Сверить реализацию с каждым пунктом `01-public-interfaces.md` и только после этого подготовить итоговое описание.

## Правило остановки

Перед переходом к следующему шагу текущий шаг должен иметь проверяемый результат. После его выполнения работа останавливается для проверки пользователем; коммиты без отдельного указания пользователя не создаются.
