# Планирование запросов кластера

Статус: черновик для отдельного обсуждения.

## Цель

Определить единый порядок допуска запросов всех клиентов к соединениям Kafka-кластера. Планировщик должен использовать доступную пропускную способность соединений без монополизации её одним продюсером, потребителем или административным клиентом.

## Границы

Входят очереди ожидающих запросов, распределение мест незавершённых запросов на каждом соединении, справедливость между экземплярами клиентов и видами запросов, отмена ожидания, закрытие клиентов и наблюдаемость.

Не входят формирование Produce-пакетов, последовательности идемпотентного продюсера, логика потребительской группы и протокольная обработка конкретного запроса. Эти подсистемы передают запрос для допуска и получают результат его выполнения.

## Связь с клиентами

`CommonConfig.MaxInflightRequests` задаёт физическую ёмкость одного соединения. Он не принадлежит конкретному клиенту. Продюсер, потребитель и административный клиент не отправляют запрос непосредственно по числу свободных мест: они передают его планировщику.

После допуска планировщик гарантирует неделимую запись кадра и сопоставление ответа с запросом. При освобождении места он выбирает следующий запрос по согласованной политике. Ожидание допуска не должно удерживать сетевой цикл и не должно обходить сроки конкретной операции.

## Требующие решения вопросы

1. Политика справедливости: циклический выбор, взвешенное распределение либо иной алгоритм.
2. Единица справедливости: экземпляр клиента, вид клиента, тема, раздел темы или запрос.
3. Приоритеты управляющих, потребительских и Produce-запросов.
4. Предельный размер очередей и результат при невозможности допустить запрос до его срока.
5. Поведение при закрытии соединения, отмене ожидания и смене лидера.
6. Метрики ожидания, занятости соединений, отказов и фактов вытеснения.

## Условия завершения

Проверки подтверждают отсутствие смешения кадров, ограничение числа незавершённых запросов, отсутствие голодания при постоянной нагрузке нескольких клиентов и корректное завершение запросов при закрытии соединения.
